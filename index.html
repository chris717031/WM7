Healthcare Endpoint Security Patching Strategy & Action Roadmap

• 漏洞高度集中現象：分析顯示，全院高危險弱點多數來自少數高普及率之標準軟體（如舊版 7-Zip、Adobe Reader、Chrome、Firefox 及舊版 Office 元件）。威策維護服務團隊建議透過版本統一發送，可在短期內阻斷近七成已公開之遠端代碼執行攻擊路徑。

• 核心業務系統特殊性：門禁刷卡管理（701Client/Server）及特定檢驗儀器主機因具備醫療業務不中斷限制，無法貿然重開機或實施未經驗測之全面更新，需特別規劃相容性驗證機制。

二、 分階段修補規劃與處置方針 (Phased Patching Plan)

第一階段 (T+7 日)

高危通用軟體自動派送更新

處置標的：7-Zip、Firefox、Google Chrome、Microsoft Edge 等非業務綁定工具。
修補手段：利用威策維運系統於夜間離峰時段實施靜默批次更新，目標快速收斂 65% 以上已知 CVE。

執行方式：全自動化派送 / 免人工干預
第二階段 (T+30 日)

醫療臨床與門禁專案排程驗測

處置標的：701Client/Server、急診/ICU 專案主機及檢驗連線軟體。
修補手段：由威策維護（MA）服務團隊協同各院區資訊組先於測試機完成連線驗證，確認無相容性衝擊後，排定科室離峰維護視窗人工更新。

執行方式：相容性實測 + 威策團隊到場排程
第三階段 (常態化)

未分配端點歸戶與白名單隔離

處置標的：歷史遺留 Java 8 外掛與「未分配」端點主機。
修補手段：啟動資產實名化歸戶排程；針對無法升級之歷史老舊系統實施應用程式白名單與 VLAN 微隔離保護，防範橫向感染。

執行方式：實名歸戶 + 補償性微隔離防護
